# M3: self-supervised PoseNet and DepthNet

Owner: Suryansh Bajaj (`@OptimusCoder10`). Implementation date: 11 October 2026.
This section describes the implementation; it does not claim trained results.

## Inputs and architecture

M3 uses the frozen scene split and shared VKitti2 loader at 128x416, Camera_0.
Each window is three chronological frames `[t-1,t,t+1]`. This corrects the
submitted interim report's five-frame description and follows the original
handoff and current config. The 4,224 training RGB frames yield 4,200 windows;
validation yields 231 windows, and test yields 835 windows over 837 frames.

DepthNet receives only the middle image, with the existing ImageNet
normalization. Its independently implemented ResNet18 encoder exposes features
at /2, /4, /8, /16 and /32. It loads torchvision's ImageNet-1K V1 weights and is
fine-tuned. Five decoder stages use widths 256,128,64,32,16, nearest-neighbour
upsampling to explicit skip dimensions, reflection-padded convolutions and ELU.
Sigmoid heads predict disparity at full, half, quarter and eighth resolution.
Depth is `1 / (1/max_depth + disparity * (1/min_depth - 1/max_depth))`, bounded
by 0.1 and 100 in the model's arbitrary learned scale. The four-scale model has
25.648026 million trainable parameters, counted locally.

PoseNet uses the existing six-channel PairEncoder for ordered pairs `[t-1,t]`
and `[t,t+1]`. Shared pooled features pass through a 512->256->6 head, with ReLU,
no dropout, small nonzero final weights and a 0.01 output multiplier. Outputs
are `[tx,ty,tz,rx,ry,rz]`, with translation first and axis-angle radians.

## Geometry and RGB-only objective

Outputs obey the shared chronological `T_i->i+1` point-transform convention
(camera x right, y down, z forward). Previous-frame reconstruction uses the
analytic matrix inverse of `T_0->1`; next-frame reconstruction uses `T_1->2`.
Negating a pose vector is not a valid replacement for matrix inversion.
Existing projection/warping code is consumed unchanged. Absolute GT poses in
the actual loader are camera-to-world, unlike the stale original plan text.

Every disparity head is upsampled to input resolution before depth conversion
and reprojection; therefore the same input-resolution K and K_inv apply at
every warp. Warping retains the shared `align_corners=True` convention. Native
resolution geometry tests independently check scaled K and its inverse.

Each source residual combines 0.85 times `(1-SSIM)/2` with 0.15 times RGB L1.
SSIM uses 3x3 support and constants 0.01 squared and 0.03 squared. Invalid and
behind-camera projections are excluded before choosing the minimum reference
error. Validity is eroded by the SSIM support. Automasking keeps only pixels
whose reprojection beats the minimum unwarped source residual by more than
1e-6; exact ties are excluded deterministically. An empty mask produces a
connected zero photometric term, with active/valid coverage logged separately.

Smoothness penalizes gradients of mean-normalized native disparity, weighted
by `exp(-abs(image_gradient))`. Its coefficient is 1e-3 / 2**scale. The final
loss is the mean over scales of photometric plus weighted smoothness. The
photometric mean is normalized by active pixels per image; this reduction and
the deterministic tie policy are explicit implementation choices rather than
an assertion of byte-for-byte equivalence to the reference code.

Images are denormalized using device-moving M3 buffers. Sensitive geometry,
depth conversion, SSIM and reductions execute in FP32. Neither forward nor
loss reads ground-truth pose or depth. Production uses pretrained encoders;
the CPU smoke config deliberately uses random weights and is not an experiment.

## Training and evaluation protocol

Baseline: seed 42, Adam at 1e-4, weight decay 1e-4, clipping norm 1, batch 8,
60 epochs, StepLR at 45 with gamma 0.1, FP32 and augmentation disabled. The
existing validation Sim(3) ATE hook selects best.pt. Pose labels are used for
validation selection, not the training objective. Automatic early stopping
is not implemented. CUDA grid-sampling backward can be nondeterministic, so
seed/RNG preservation does not guarantee bitwise-identical GPU reruns.

Shared checkpoint-resume and depth-evaluation changes are delivered as separate
review bundles and are not applied to other members' source files on this branch.
After those PRs land, depth is opt-in through the same evaluator. It scores all
unique frames, including endpoints, from two-frame dataset windows via
predict_depth. GT is nearest-neighbour resized to 128x416. Evaluation uses no
Eigen/Garg crop, valid GT in (0.001,80) metres, and image-level averaging.
Primary depth scores use per-image GT-median scaling; secondary scores retain
raw predicted scale. AbsRel, SqRel, RMSE, RMSE-log and delta thresholds are saved.
Nonfinite predictions fail, empty GT frames are counted, and entirely empty
evaluations fail. The loader's centimetre conversion and invalid-depth masking
are tested without changing its implementation.

Photometric training cannot recover absolute scale: jointly scaling depth and
translation leaves image reconstruction unchanged. The handoff and current
comparison footnote's claim that M3 recovers metric scale from its own depth is
incorrect. Report Sim(3) ATE for trajectory shape and scale-fixed SE(3) ATE;
existing RPE/drift remain unscaled and therefore scale-sensitive. No test-depth
median factor is applied to the pose trajectory. The shared comparison footnote
correction is part of the depth-evaluation review bundle.

Scene20 rain/fog/rotated variants are robustness tests of the same route, not
independent trajectories. They remain held out; the report's proposed angle
augmentation is outside this baseline. The local subset has no depth PNGs, so
depth scoring requires the official archive or a prepared subset, not a change
to the RGB training loader.

## Evidence and attribution

Tests cover shapes, pretrained-flag behavior, geometry, masks, all-scale gradients,
label independence, synthetic optimization, shared-trainer updates and sequence
reconstruction. CUDA checks run only when CUDA is present. Record a pinned code
revision, checkpoint hash/epoch, full config, software/hardware, coverage curves,
trajectory and depth/reconstruction plots for every measured experiment.

The submitted report and committed M2/M4 JSON files describe different numbers;
neither is silently overwritten by M3. Their provenance must be reconciled by
the owners before making a unified final comparison. No M3 training metrics have
been invented or inserted into the comparison table.

Architecture and loss were written independently from these papers, not copied
from upstream code. Existing shared geometry/PairEncoder were reused unchanged.
